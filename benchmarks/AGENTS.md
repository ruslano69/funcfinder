# benchmarks/

## Purpose

Measure funcfinder on real projects using independent syntax-tree references.

## Ownership

- `accuracy_checks.py` validates small C/C++/Kotlin/Ruby regressions with independent pinned tree-sitter grammars and explicit expected declarations. It requires a caller-supplied grammar runtime and Go/D binaries; artifacts stay under ignored `build/accuracy-fixed`.
- `specsheet.py` compares directory maps with the Go oracle and estimates token savings.
- `ffd/` is the D port's file/directory executable: all 15 token finders, function/type maps with file field metadata, name selection, extraction, line ranges, raw-cleaner controls, trees, `--names`/`--doc`, directory JSON, split/incremental shards, a worker pool and comparisons with Go; its contracts are in `ffd/AGENTS.md`. `reuse.d` holds the thread-local block reuse the finders and cleaners share.
- `python_ast_eval.py` compares Python function locations and ends with Python's native AST.
- `php_tree_eval.py` compares named PHP functions/methods, including bodyless declarations, with tree-sitter PHP.
- `scala_d_tree_eval.py` compares Scala definitions/declarations, D functions/constructors/destructors/postblits and Java methods/constructors/annotation elements with their tree-sitter grammars (the historical filename is retained).
- `c_tree_eval.py` compares C definitions/prototypes after GCC preprocessing, mapped back to original source lines.
- `ts_tree_eval.py` compares TypeScript functions, methods, signatures and variable-bound functions with tree-sitter-typescript.
- `js_tree_eval.py` compares JavaScript named declarations/expressions, generators, literal methods and directly bound anonymous variable functions/arrows with tree-sitter-javascript. `JAVASCRIPT_FIX.md` records the profile, pinned corpora and before/after results.
- `cpp_tree_eval.py` compares C++ functions, constructors, destructors and bodyless declarations with libclang, keeping only the active lines of `g++ -E`.
- `csharp_roslyn_eval.py` builds `csharp_oracle.cs` against the selected SDK's Roslyn assemblies and compares C# named methods, constructors/destructors, local functions and operators, including bodyless declarations. The oracle additionally emits nominal `classes` and function `header_start` after attributes, retaining full `start` spans.
- `csharp_traversal_compare.py` compares production linear scope traversal with the test-only recursive prototype through a Go overlay; it records source/binary size, in-process timing/allocations, complete CLI output equality and Roslyn results for both builds.
- `brace_pilot_build.py` builds and tests the shared C#/Java/D recursive pilot through a Go overlay, recording source/binary hashes and test/vet logs. `BRACE_PILOT.md` describes the pilot, scope and independent corpus results.
- `d_traversal_compare.py` measures the full production D parser versus the verified shared recursive pilot: serial parsing/allocations on preloaded tracked D files and paired complete directory CLI runs. Raw samples and maps stay under its ignored work directory.
- `dlang_port.d` and `dlang_port_compare.py` compare a D-only finder API port (runtime regex and ctRegex builds) with a frozen production Go API. `DLANG_PORT.md` records the results and scope.
- `dlang_predicate_check.d` differentially checks the D pilot's attribute/type/statement scanners against the previous gated regex predicates. Build it with `-d-version=PredicateCheck`, which omits the pilot's normal main function.
- `js_ts_cleaner.d`, `javascript_port.d`, `typescript_header.d`, `typescript_port.d`, `typescript_candidates.d`, `js_ts_model.d` and `js_ts_probe.d` are the experimental D JS/TS lexical/finder API. `js_ts_port_compare.py` freezes Go, compares complete lexical facts and ordered function/class/signature results, scores existing independent grammars and measures cleanup/finder/probe time. `js_ts_port_checks.py` owns fixture/stress/raw-cleanup/header-vector checks; `JS_TS_D_PORT.md` records scope and results.
- `brace_port_unicode.d`, `brace_port_cleaner.d`, `brace_port_model.d`, `csharp_port.d` and `brace_port_probe.d` support the experimental serial D C#/C++ finder API. C++ uses `cpp_tokenizer.d` and `cpp_tokens_port.d`; `cpp_port.d` retains the earlier regex experiment. `brace_port_compare.py` owns frozen-Go comparisons, Roslyn/libclang scoring and paired timings; `brace_port_checks.py` owns fixture, raw-cleanup and diagnostic pattern-group checks. `CSHARP_CPP_D_PORT.md` records scope, pins, results and Unicode provenance.
- `go_port.d` and `java_port.d` extend the shared serial probe to Go/Java without regex in normal parsing. `go_java_port_compare.py` owns frozen-Go comparisons and native Go/tree-sitter Java references; `go_ast_spans.go.txt` supplies the Go AST span oracle without creating a benchmark Go package. `go_java_port_checks.py` owns fixtures, corpus audits and C#/C++ regressions; `GO_JAVA_D_PORT.md` records profiles and results.
- `c_port.d` reuses the C++ tokenizer for recursive C declarators; `c_port_probe.d` is a separate C-only serial entrypoint. `c_port_compare.py` owns frozen-Go cleanup comparisons, GCC/tree-sitter Lua scoring, fixtures, assertion/unit builds and paired timing; `C_D_PORT.md` records coverage and limitations.
- `rust_port.d` owns the standalone Rust lexer/token finder; `rust_port_probe.d` is the serial Rust-only entrypoint. `rust_port_compare.py` owns frozen-Go comparisons, independent Rust grammar profiles, fixtures, unit/token audits and paired timings; `RUST_D_PORT.md` records source pins, profile differences and grammar exclusions.
- `kotlin_port.d` owns the standalone Kotlin lexer/token finder; `kotlin_port_probe.d` is the serial Kotlin-only entrypoint. `kotlin_port_compare.py` owns corpus/fixture/audit/timing comparisons with frozen Go and the compiler PSI oracle in `kotlin_psi_oracle.java.txt`; `KOTLIN_D_PORT.md` records profiles, toolchain and measurements.
- `swift_port.d` owns the standalone Swift lexer/token finder; `swift_port_probe.d` is the serial Swift-only entrypoint. `swift_port_compare.py` owns frozen-Go, Swift grammar, fixture/unit/token-audit and paired-time comparisons; `SWIFT_D_PORT.md` records pins, profiles, exclusions and specialization limits.
- `php_port.d` owns the standalone PHP lexer/token finder; `php_port_probe.d` is the serial PHP-only entrypoint. `php_port_compare.py` owns frozen-Go/independent PHP grammar comparisons, fixtures, unit/token audits and paired timing; `PHP_D_PORT.md` records pins, profiles and limits.
- `scala_port.d` owns the standalone Scala lexer/token finder; `scala_port_probe.d` is the serial Scala-only entrypoint. `scala_port_compare.py` owns frozen-Go/independent Scala grammar comparisons, fixtures, module/token audits and paired timings; `SCALA_D_PORT.md` records profiles, pins and Scala 3 limits.
- `python_port.d` owns the standalone Python literal/logical-statement/indentation finder; `python_port_probe.d` is the serial entrypoint. `python_port_compare.py` owns native AST scoring and a frozen production PythonFinder adapter, module/token checks and paired timings; `PYTHON_D_PORT.md` records pins, profiles and normalization limits.
- `ruby_port.d` owns the standalone Ruby literal/heredoc/token/block finder; `ruby_port_probe.d` is the serial entrypoint. `ruby_port_compare.py` owns frozen-Go/independent Ruby grammar comparisons, heredoc span normalization, fixtures, units/audits and paired timing; `RUBY_D_PORT.md` records pins/profiles and lexical limits.
- `brace_parallel_compare.py` builds the optional scope-parallel overlay and compares file/scope worker combinations with verified production and serial-pilot binaries. `--language cs|java|d` selects corpus parity for all `--root` projects (default `d`); `--parity-project language=path` adds other parity corpora. `BRACE_PARALLEL.md` records the scheduler, results and limits.
- `java_finder_compare.py` compares before/after Java CLI binaries and an optional frozen pilot with one/CPU-count file workers, repeated shuffled rounds and stable per-variant output. It retains maps, counts, pins and source/binary hashes. `JAVA_FIX.md` records the production fix, independent quality checks and timing limits.

- `searchserver/` contains the existing search-server load harness.

## Local Contracts

- `findCSharp(facts, includeFunctions = true)` retains function recognition/end checks and body markers for type
  traversal. Type-only requests may omit result rows, conditional ranges and expression-alternative output ends.
  Roslyn types include class/struct/interface/enum/record declarations, with full attribute/modifier starts and body
  closing-brace ends (syntax ends for bodyless types). Keep delegate/alias scope and inactive rows explicit. Function
  `start` remains the full Roslyn span; additive `header_start` normalizes the existing attribute-skipping convention.

- `findJava(facts, includeFunctions = true)` controls method/constructor-result emission. Type-only requests retain
  recognition/end scans/scope traversal for local/anonymous classes, records and enum members. Preserve default full
  behavior and file ownership context; independently verify named type starts/ends and nested visibility.

- `findGo(facts, includeFunctions = true)` retains full behavior by default. Type-only consumers may skip function
  recognition/results because the token loop still traverses the entire input; preserve local/grouped/alias types.
  `ffd` alias discovery/separation and file ownership contexts remain independent, required work.

- `findCppTokens(..., includeFunctions = true)` controls function-result emission only. Keep function recognition,
  parameter/end validation and body skipping for type-only requests to preserve local-type analysis scope. Default
  full API behavior and owned `ffd` results remain unchanged; audit complete types against full results.

- `dlang_port.find(original, includeFunctions = true)` preserves its full API by default. Types-only requests retain
  shared preparation and class discovery, skipping subsequent function recognition/materialization/ownership only.
  Do not remove header joining, hints or contract masking without separate type visibility/span checks.
- The standalone D batch `main` currently retains borrowed function names across arena resets. Until repaired,
  isolate each source file when scoring its saved API maps; never treat corrupted multi-file batch output as parser
  accuracy. `ffd.toSyms` owns names before the next file; preloaded timing consumers must consume/copy results likewise.
